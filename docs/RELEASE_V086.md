# Mahjong Wild UI 0.8.6 - full-frame portrait

## Cause and scope
UI 0.8.5 used `min(100vw, availableHeight * 864 / 1859)` for the entire stage.
On a short Safari content viewport that forced a narrower centered game, leaving
plain side gutters. This release replaces the height-derived mobile width cap
with a viewport-width stage and a separate responsive layout for the crown,
multiplier rail, reel frame, result/meter panels and controls.

The current approved artwork is the only visual source. The master reference
is not edited. Protected crown/control pixels are uniformly scaled. Decorative
edge extensions are crops of the original sky/clouds, not a new concept image.
The board's side ornaments adapt independently of the live tile grid.
On short viewports, the extra crown/footer clouds blend into a softly blurred
color strip from the source edge. This softens decorative joins without
duplicating controls or changing any protected center artwork pixels.

## Preserved behavior
- 23 authoritative tiles; 4/5/5/5/4 columns; exact face ratio 2:3.
- Circular Spin disk, undistorted logo, brighter x2 and immediate input.
- Soft Tech / Continue Play, sound preferences, menus and opt-in diagnostics.
- Math 0.8.0, weights, multipliers, replay, virtual-credit-only economics.
- No new spin request or retry can be issued by the layout module.

## Viewport handling
Portrait occupies the complete browser content viewport. In a browser tab,
visualViewport height changes reflow the same controls without changing outcome
state. In installed standalone mode the artwork uses the full layout viewport
and `100lvh`, so a smaller transient visualViewport cannot leave an unpainted
status/home region. The root backdrop also covers the screen independently of
the game stage; safe-area insets are never applied as padding around that
backdrop. A real board
geometry change can retire a transient reel atlas; the accepted server round
still settles exactly once. Pinch zoom is not overridden. Landscape keeps a
legible portrait game centered over the full background rather than stretching
mahjong faces sideways. Browser chrome and OS indicators remain native.

Notch/home safe areas use decorative extensions. The left/right safe insets
also constrain the board and interactive controls without removing the outer
artwork. Nearly square or split-screen viewports reserve header/control space
before sizing the board; they cannot consume that space and collapse the
controls to zero height. Desktop WebKit, synthetic standalone mode, and
injected safe-area values are regression checks, not a physical iPhone
certification. Native Safari toolbars remain browser-owned; launch the installed
Home Screen app to use the standalone canvas behind status/home indicators.

## Build and verification
Append `python tools/build_fullframe_ui.py` after the existing v085 build sequence.
Use `--runtime-only` in the production Docker stage. The build updates release
labels in generated QA files; invariants about real outcomes and asset identity
remain checked. Run `python -m unittest discover -s tests -q` plus the existing
motion/audio/input suites and `python tools/qa_fullframe_v086.py` for Chromium
and WebKit. Offline mode is only the sandbox transport fallback.

Release evidence is generated by the CI run and `qa/live_results.json`; do not
interpret this document as evidence that a deployment or iPhone test finished.

## Recovery of the blocked browser gate

The first v0.8.6 build retained two generated v0.8.5 assertions that required the
whole stage to keep a fixed 864/1859 ratio. Those assertions conflict with a
stage that fills the portrait viewport. The v0.8.6 build now replaces both with
the shared full-frame geometry checks: viewport containment, no page overflow,
23 tile faces at 2:3, an undistorted logo and Spin disk, ordered panels and
controls inside their safe area. The v0.8.5 source hashes remain checked before
this transformation. Unexpected QA source changes fail the build.

The same full-frame CSS and layout script are loaded by the offline fallback.
Resize may interrupt the transient reel animation before all columns begin;
the test still requires ordered actual starts, exactly five final stop events,
one accepted spin, the authoritative final board, and valid replay. Normal
spins retain their complete sequential start/stop checks.

Every full-frame viewport test collects JavaScript errors from before page
load. The full-frame checks also verify the artwork bands and decorative
extensions, rather than accepting an empty rectangle as proof of coverage.
Exact live-release verification now checks 32 file hashes, including the
service-worker cache version, manifest, PWA script, root styles, backdrop, and
top/bottom extensions, before checking a real HTTPS spin and replay. It also
checks the actual viewport and standalone status-bar metadata.
The existing large-balance regression also exposed an absolute font-size floor
that enlarged and clipped counter text in narrow landscape stages. Counter
fitting now respects the measured field width, preserving the full value.
Builds must start from a clean checkout: generated QA/runtime derivatives must
not be committed over the integrity-checked source files.

An already-open installed app can retain the earlier document in memory.
Worker activation does not replace that document. A release check must confirm
the served version, and a user should close and reopen the installed app after
an update. No automatic reload is introduced during a spin.

multipliers or economic controls are changed by this UI release.
